# คู่มือเพิ่มข้อมูล MVP 2

ทุกคำสั่ง npm ทำใน `E:\debate\web` เนื้อหาอยู่ใน `web/src/data/` เปลี่ยนข้อมูลแล้วต้อง build/deploy ใหม่ ไม่มีหน้า admin ใน MVP นี้

## การแข่งขัน

ต้นทางคือ Excel ที่ผู้ใช้ยืนยัน:

`การแข่งขัน/สรุปการแข่งขันโต้วาทีคณะวิศวะ_2017-2026_ฉบับวิเคราะห์ทุกนัด.xlsx`

ใช้ Python ที่มี openpyxl และ Pillow:

```powershell
python tools/import_competitions.py "..\การแข่งขัน\สรุปการแข่งขันโต้วาทีคณะวิศวะ_2017-2026_ฉบับวิเคราะห์ทุกนัด.xlsx" --output src/data/competitions.json
```

นำเข้า `ผลการแข่งขัน` และ `สรุปรายปี` โดยตรง เก็บ fingerprint ของ workbook และลิงก์คลิป/หลักฐาน ไม่อนุมานผลเพิ่ม การนำเข้ารักษา metadata cloud เดิมไว้ จำนวนปัจจุบัน 43 รายการ = Freshy 42 + Visionary 1

หน้าแข่งขันเรียงปี 2017 → 2026 และลำดับรอบตาม Excel รอบคัดเลือกก่อนน็อกเอาต์ ตารางคู่ปรับคำนวณจากชุดเดียวกัน แพ้มากก่อน → พบกันมากก่อน → ชื่อคณะ มีตัวกรองปีและรายการ

## ทำเนียบ

แก้ `rosters.json` ปีละ **6 คนเท่านั้น** คนชุดนี้เป็นทั้งสมาชิกและนักโต้ ระบบตรวจจำนวนก่อนสร้างหน้า ห้ามลบ record เพียงเพราะยังไม่มีรูปหรือชื่อ

```json
{
  "id": "2026-01",
  "nickname": "ชื่อเล่น",
  "fullName": "ชื่อจริง นามสกุล",
  "quote": "ประโยคสั้นของคนนี้",
  "instagram": "https://www.instagram.com/username/",
  "bio": "ประวัติสั้น (ไม่บังคับ)",
  "portrait": "member-2026-01"
}
```

`portrait` อ้าง ID ใน `media.json`; ค่าว่างยังแสดงช่องรอข้อมูลโดยไม่สร้างบุคคลสมมติ ระดับปีมี `quote` และ `groupImage` สำหรับข้อความและภาพทีม

## ลงทะเบียนรูปในเครื่อง

จัดต้นฉบับตามหมวดและปีได้ตามสะดวก เช่น `ทำเนียบสมาชิก/2026/`, `งานแข่ง/2026/`, `กิจกรรมต่างๆ/2026/ชื่อทริป/`

```powershell
npm run media:add -- --id=member-2026-01 --file="E:\debate\ทำเนียบสมาชิก\2026\01.jpg" --alt="คำบรรยายภาพบุคคล" --credit="เจ้าของภาพ"
```

คำสั่งนี้ลงทะเบียนสำหรับ local preview เท่านั้น เพิ่ม `--approved` เมื่อรูปนั้นพร้อมเผยแพร่จริง อาจเพิ่ม `--caption="คำบรรยายใต้ภาพ"` ได้ ID ใช้อักษรอังกฤษ ตัวเลข `_` หรือ `-` และห้ามซ้ำ

จากนั้น restart `npm run dev` เพื่อสร้างรูปย่อ WebP ในเครื่อง ต้นฉบับไม่ถูกแก้ไข `media.json` เก็บข้อมูลสาธารณะ ส่วน path ต้นฉบับอยู่ใน `.local/` ที่ไม่เข้า Git

ภาพผลแข่งและ artwork ที่รอสิทธิ์เดิมยังเป็น `publishable:false` ตาม D21 รูปสำหรับ production ต้องตั้งสิทธิ์และเครดิตให้พร้อมก่อน

## อัลบั้มกิจกรรม

เพิ่ม object ใน array `albums.json` หลังลงทะเบียนรูปแล้ว ตัวอย่างแม่แบบนี้ไม่ใช่กิจกรรมจริงที่ใส่ไว้ในเว็บ:

```json
{
  "id": "outing-2026-01",
  "year": 2026,
  "date": "2026-09-01",
  "category": "trip",
  "title": "ชื่อทริป",
  "description": "คำบรรยายสั้น",
  "cover": "outing-2026-01-a",
  "photos": ["outing-2026-01-a", "outing-2026-01-b"],
  "rosterYear": 2026
}
```

category: `meal` กินข้าว, `trip` ทริป, `graduation` รับปริญญา, `other` อื่น ๆ หน้าเรียงล่าสุดก่อนและกรองปี/หมวดได้ gallery แสดง caption ของแต่ละภาพ ใช้ลูกศรหรือ ESC และปิดกลับไปปุ่มเดิมได้

ภาพแข่งขันที่เป็นบรรยากาศสามารถใส่ในอัลบั้มและเชื่อมปีได้ ส่วนหลักฐานผลแข่งอ้างจาก `images` ของ match ในชุดข้อมูลการแข่งขัน อย่าเดาเจ้าของภาพหรือบุคคลจากชื่อไฟล์

## การส่งต่อ

ส่งต่อ repo พร้อมข้อมูลและ lockfile ส่วนต้นฉบับและ `.local/media-sources.json` ส่งผ่านพื้นที่ที่จำกัดสิทธิ์ หรือให้ผู้ดูแลใหม่ลงทะเบียน path ของตนเอง หาก cloud พร้อมแล้วใช้ metadata เดิมสร้างเว็บได้โดยไม่ต้องมีต้นฉบับทุกภาพในเครื่อง ดู [คู่มือ Cloud](CLOUD_MEDIA.md) สำหรับ API secrets และขั้นตอนเผยแพร่
